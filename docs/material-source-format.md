# 教材來源格式 v1

已依使用者的 implement 授權實作本格式。每筆只需句型、用途及例句；先前四個必填欄位、一教材一檔及 notes 陣列提案已由此格式取代。JSON 是可編輯來源，SQLite 保存已接受版本和進度；新教材預設 High。

## 1. 最小格式

一份來源輸出一個 UTF-8 JSON 檔，可包含任意筆教材，不要求 100 筆或固定分組。

```json
{
  "format": "sentence-materials/v1",
  "source": "教材名稱、來源網址或原始檔名",
  "items": [
    {
      "pattern": "I think + clause",
      "purpose": "表達自己的看法或判斷。",
      "examples": ["I think we need more time."]
    }
  ]
}
```

每筆只必填三項：

| 欄位 | 型別 | 意義 |
|---|---|---|
| `pattern` | 非空字串 | 可重複使用的英文句型；使用一般文法符號即可，不是程式匹配規則 |
| `purpose` | 非空字串 | 這一筆要練的溝通用途，以簡短繁體中文表達 |
| `examples` | 非空字串陣列，至少一項 | 符合該用途的完整英文例句；多個例句分開保存 |

三個選填欄位：

| 欄位 | 型別 | 何時填 |
|---|---|---|
| `notes` | 非空字串 | 有重要變體、限制或用法差異時；一段文字即可 |
| `id` | 本地 ID 字串，如 `S001` | 遷移既有教材或修訂指定本地教材時；新來源省略，由程式配發 |
| `priority` | `Core`、`High` 或 `Useful` | 原教材已有優先度，或使用者明確指定時 |

整份檔案只填一次 `format` 與 `source`。`format` 是固定版本字串；`source` 是人可辨識的來源描述，不作唯一身份鍵。原始檔、網址、頁面位置及轉換紀錄由匯入檔案保存與核對流程追溯，不塞進每筆教材。

省略沒有內容的選填欄位，勿填 `null`、空字串、`—` 或「待補」。範例只為格式展示；[新來源範例](../examples/material-pack-v1-new.json) 與[既有教材範例](../examples/material-pack-v1-legacy.json) 均未匯入。

## 2. 教材的單位

一筆教材代表一個可辨識的練習用法。`pattern` 描述形式，`purpose` 界定焦點；同形式但不同溝通用途可以分成兩筆，不能只靠句型字串去重。

同一用途的肯定／否定變體、合理時態變化及補充例句，通常放在同一筆的 `notes`／`examples`，不為每個表面變形建立新掌握單位。若來源把不同用途或重要對比放在一起，AI 先提出拆分建議；既有教材不得自動拆分或合併 IDs。

`pattern` 可沿用 `clause`、`NP`、`V-ing` 等符號；不另設 slots、固定題庫、答案清單或字首匹配規則。教練結合用途、例句及 notes 產生中文情境並判斷回答，不能把「沒有出现在例句」當作錯誤。一個例句即可入格式；更多例句有助理解不同用法，但不設硬性配額。

重要 notes 必須保留：S001 的一般否定變體，以及 S089 的三種 modal 並非處處互換等限制。`examples` 保留全部有效例句；不能用第一句覆蓋多行 Example。空白 Notes 則省略。

## 3. 為何不再加欄位

不要求 tags、group、level、family、難度分數、信心分數、欄位來源標籤、版本 hash 或建立日期。這些不影響一筆教材是否足以練習；原始來源已有的資訊仍完整留存，必要時再呈現。

優先度是已確認選題政策需要的唯一選填排序資料。既有 Core／High／Useful 原值保留。新教材沒有 priority 時，統一以 High 參與選題，並標明它是系統預設而非原作者判斷。AI 不自行推測 Core 或語言程度。

掌握狀態、成功次數、複習日期、弱點及練習紀錄屬學習資料，不接受混入教材檔。Review Flag／Concern／Recommendation 屬整理建議，保存在轉換報告與原文，不自動變成 notes 或可執行命令。

## 4. AI 轉換約定

使用者可以提供文字、Markdown、表格、文章或已取得可讀文字的文件，請 AI 產生相同格式。閱讀不到的檔案或段落須明列；不能宣稱已完整轉換。

AI 可從來源例句歸納句型形式，並用繁體中文摘要其用途；不要求原文已包含欄位名稱。保留原例句、語用差異及重要限制，僅整理排版，不默默修正疑似錯誤。無法確定的解讀列在報告，不硬填進教材。

預設採來源已有例句。來源缺少可用例句時，AI 可另外提出補充候選及理由，由使用者審閱後才納入；不把新造例句說成摘自原文。省略、拆分、合併建議、疑似錯誤及 AI 補充均在簡短轉換報告交代，不為每筆增加來源／信心欄位。

轉換交付兩份內容：

1. 一份可解析的教材 JSON，僅含格式允許欄位。
2. 一份簡短報告：原來源範圍、已轉換筆數、歸納方式、遺漏／待確認項目與補充候選；有需要時用 `items[0]` 等位置對應來源頁碼或段落。項目位置僅供本批審閱，不是永久 ID。

報告屬匯入核對資料，日常練習不必載入。若有待確認內容，先保存草稿並回報；不得默默只匯入一部分。格式轉換本身不構成正式匯入授權；日後新增或修改先預覽供使用者接受。

## 5. 新增、重複匯入與修訂

| 情況 | 預定行為 |
|---|---|
| 新來源沒有 `id` | 核對後配發未使用過的本地 ID，初始狀態 New；回傳附 ID 的同格式檔案，之後修訂使用該 ID |
| 匯入同一份內容 | 依原始檔案及正規化內容核對已接受批次／教材，沿用映射，不新增一輪教材或進度 |
| 無 ID 的內容與本地完全相同 | 沿用既有教材並追加來源關聯；本批有重複項時列出位置供整理 |
| 形式相近但用途或內容不同 | 提出可能重複或相關的對比，不自動覆蓋、合併或共用掌握成果 |
| 明確指定已存在的 `id`，內容完全相同 | 不重複寫入；若僅來源不同，保存來源關聯 |
| 明確指定已存在的 `id`，內容變更 | 提出修訂差異；使用者接受後建立新版本，保留原版本及進度 |
| 提供不存在或衝突的本地 `id` | 回報衝突，不假定它是其他來源的新教材 ID；既有 S001–S100 初次遷移走專用核對流程 |
| 目標句型或用途實質換成另一種能力 | 提出新教材而非沿用舊 ID；不把舊進度接到新目標 |

ID 永久保留、不回收；排序位置、檔名及來源標題不能代替 ID。外部教材的原 ID 保存在原始來源／核對映射，不由 AI 複製成同名本地 ID。新來源內容變了且沒有提供本地 ID，先核對候選，不猜它是修訂。

回合固定開始時使用的教材版本；增加例句或修改說明不重評歷史，不重設掌握。停用教材保留歷史引用；合併、拆分、刪除及進度轉移需另有具體方案。正式匯入前提供新增／相同／修訂／衝突／待確認摘要。

## 6. 格式檢查與內容審閱

[JSON Schema](../schemas/material-pack-v1.schema.json) 定義可機讀的欄位與型別；拒絕未知版本、額外欄位、缺少必填資料、空白文字、錯誤型別和空例句陣列。JSON parser 另須拒絕重複鍵，避免後值默默覆蓋前值。

還需內容及本地參照檢查：ID 是否唯一／已存在、例句與句型／用途是否一致、來源是否有遺漏、重要限制是否保留，以及相近教材是否需要對比。JSON Schema 無法證明文法正確或練習目標相同；不同物件的 ID 唯一也需另外檢查，而非用 `uniqueItems` 代替。[JSON Schema 官方規範](https://json-schema.org/draft/2020-12/json-schema-validation) 中的陣列唯一性比較完整元素。

實作以標準 Draft 2020-12 validator 驗證 schema 和範例，公開操作另驗證重複 ID、本地参照及佔位字。語言內容及來源完整性仍由 AI 核對並提出報告，使用者審閱後才接受，格式有效不代表語言正確。

## 7. 舊來源映射

| 原資料 | 本格式或保存位置 |
|---|---|
| Structure ID | `id`；保留 S001–S100，練習紀錄仍指向原 ID |
| Pattern／Function | `pattern`／`purpose` |
| Example | `examples`，依實際完整句子拆分，非機械地把每個換行當新例句 |
| 有實質內容的 Curriculum Notes | `notes`；空白及 `—` 省略 |
| Priority | `priority`，保留原值 |
| Group／Level／Review 欄位及其他來源內容 | 原始來源與核對資料；重要用法另確認納入 notes |
| Mastered State／計數／日期／Error／Session | SQLite 學習資料，不放教材包 |

現有100筆教材與14筆歷史／錯誤頁面共114頁均已取得並重讀核對；原始 properties、正文、schema、舊文件及更正鏈留在本地 data/imports。缺失的實際練習時間與原 ChatGPT 逐字稿不補造。

## 8. 已實作的接合

匯入草稿與已接受教材共用同一種 JSON 格式；系統配發 IDs 後輸出可維護的版本。一份來源一檔，放在 `materials/`，無須手動拆成 100 個檔案。只有經驗證且接受的版本才供下一回合使用，避免直接讀到未完成編輯。

教材 JSON 是可編輯來源；SQLite 保存進度、紀錄、ID／來源映射及已接受教材版本快照，不提供另一條獨立修改教材的入口。原始檔與轉換報告另存匯入資料。發布與恢復由公開操作實現，不加進 AI 的教材欄位。

日常由單一 plugin 執行轉換及練習；使用者不需載入額外指揮文件。
