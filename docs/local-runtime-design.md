## 1. 完成後如何使用

在本 Codex 專案聊天中說「開始句型練習」。日常用自然語言操作，不需自行管理檔名、回合 ID、卡片或 JSON。英文回答可透過 Codex 聽寫送出；教練依收到的文字及明確更正評估。

| 意圖 | 行為 |
|---|---|
| 開始／繼續 | 有未完成回合時簡短提示並接續；否則讀本地資料選題，顯示目標、理由與第一題 |
| 暫停／晚點繼續 | 保存已有內容，保留未完成回合，停止出題 |
| 結束／今天到這裡／幫我收尾 | 停題、結算、驗證保存，回覆簡短成果及複習日期 |
| 換新一回合 | 先結算舊回合；成功後再開始新回合 |
| 同步／幫我保存 | 視同收尾：結算並驗證本地保存；只是問「保存了嗎？」則查狀態 |
| 看進度 | 顯示本地狀態、到期項目、已確認弱點及必要資料缺口，不改進度 |
| 聽寫誤辨識更正 | 保留原文、明確更正與原因，按第 7 節處理 |

自然語言不要求逐字匹配。只有讀取查詢不會自動結算回合。同一專案只有一個未完成回合；兩個聊天同時操作時，程式檢查題目與資料版本，避免把過期回答套入不同題目。

一般回覆形式：

- 開始：「今天練 [ID／Pattern]，因為 [選題理由]。第一題：[中文情境與意圖]。」新句型另給簡短用途與例句；複習先提取，再揭示參考。
- 每題：一句主要判斷、必要修正或重試要求，再給下一題。不顯示長計分表。
- 收尾：「已保存。這回合 [有證據的進步]；[需提示或未測部分]；下次複習 [日期]。」只有驗證成功才稱已保存。

以上為格式示意，不是實際練習成果。完整證據可按需查看本地紀錄。

## 2. 題目與回合預算

最終目標是真實情境的自然表達，既有 100 個句型是各回合焦點。題目提供中文背景與表達意圖，使用者自行組織英文，不要求逐字翻譯。

預設 4–6 個情境，一個主句型，最多穿插一題舊句型提取；尾段提取也包含在預算內。重試是另一個回答，不是新情境。可依表現縮短，使用者隨時能結束，不追加題目湊數或補考。

每回合最多嵌入一個已有跨回合證據、且適用於本回合的反覆弱點；它隨情境自然出現，共用預算。挑選以適用性為先，再考慮句型／意思障礙、已驗證 occurrence 回合數、較久未見及穩定 key。首次適用機會之前不揭示所需修正。第一次新錯誤仍可回饋及留觀察，不增設多條補強路線。

糾正先處理句型／意思，再挑一個高價值問題。句型或意思錯誤通常安排有用重試；小問題可簡短提示後繼續。使用另一種正確英文說法時，承認其成立，再引導用本題句型重說；不把正確替代說法列為文法錯誤，也不當成已驗證的目標句型成功。

## 3. 選題

每次新回合讀一個一致的本地資料視圖。候選必須有實際教材；讀取失敗不當空資料。

1. 使用者明確指定目標優先，允許指定未到期句型提前練習，簡短記理由。
2. 有其他合格候選時，排除上一個已結算真實回合的主句型。
3. 到期複習優先；沒有到期項目就學新句型。若最近兩個回合確定都是複習，且有新句型，則換新。未知目的不當複習，也不跳過未知回合湊連續紀錄。
4. 到期候選依日期較早、已支持的未解句型／意思障礙、ID 排序；新候選依 Core／High／Useful、ID 排序。
5. 自動穿插的舊句型從其他到期項目取最多一個；使用者可明確指定穿插目標。時間不足或結束時可略過，未實際作答不算練過。

Date-only 複習日期依 Asia/Taipei；datetime 依實際時刻比較。Active 弱點或 Learning 本身不把未到期項目變成到期。缺日期標記 scheduling gap，不猜日期。

沒有其他合格候選時，唯一到期的上一個主句型可再次使用，但換情境。全部已練且尚未到期時，說明下一個到期日，讓使用者指定提前練習；不擅自製造新教材。泛稱「複習」但無到期候選時亦說明可用選項，不默默改成新課。

最近回合使用已支持的日期／結束時間或原來源 createdTime 排序；行政排序時間不拿來冒充實際練習時間。遇會改變選題的已知順序矛盾，只處理該缺口，不猜補歷史。

## 4. 回答、提示與提取證據

逐題保留題目、原回答、聽寫更正、回饋、提示種類、重試關係、穩定 attempt ID、兩軸結果及時間來源。完整原文先保存，評估與回饋再保存；中斷時可知道停在哪個階段。

- 句型獨立成功：沒有本題句型提示，句型與目標意思正確。
- 整體獨立成功：沒有靠實質提示或修正，完成句型正確、意思清楚的表達。小錯可另記。
- 句型提示、其他語言提示及範圍未知提示分開記；同一協助動作只計一次，有句型提示則歸句型。
- 示範、提示後同題重說不算獨立成功；後續新情境可重新觀察獨立運用。無關提示不取消已支持的句型獨立成功，但可影響整體獨立成功。
- 一般立即自修不拆成多次回答；明確完整重試才另建 attempt 並連結原題。聽寫更正不是多一次練習。
- 尾段新情境保留首次 target／expression 的 pass、fail、not_tested 或 unknown；後續回饋與重試不覆寫首次結果。
- 未知保留未知，不能當零、失敗、成功或弱點解除。已觀察且沒有項目與未取得證據分開表示。

結果以本地新政策 `local-practice-v1` 標示；儲存 schema 與教學 policy 分開版本化。匯入紀錄保留原 schema／policy 及正文。舊缺欄位可在相容讀取中呈現未知，不回寫成新版本。

## 5. 延遲提取與掌握

延遲成功須為後續回合該句型首次實際提取、整體獨立成功、新情境、事前沒有該句型例句／提示／排練，距最近一次實際相關練習至少 24 小時。穿插練習及未結算但已保存的實際練習也更新最近練習基準，不跳過較近期未知練習。

有可靠實際時間則直接比較；否則只接受可證明間隔的保守界限：本次題目輸出前時間是下界，前次實際練習後的已驗證保存／結算時間是上界。這些時間仍標為界限，不稱為實際口說時間。時間未知、剛跨午夜或暖身後成功均不滿足延遲門檻。不要求使用者填 optional 時間。

| 狀態 | 升級門檻 |
|---|---|
| New → Learning | 已有實際有效練習 |
| Learning → Usable | 至少 2 個整體獨立成功回合、累計至少 3 次整體獨立成功、2 個不同情境、至少 1 次延遲成功 |
| Usable → Automatic | 至少 3 個整體獨立成功回合、至少 2 個不同回合的延遲成功；最近兩個相關回合首次提取均整體獨立成功，且曾依情境改寫或延伸 |

升到 Usable／Automatic 共同需本回合尾段整體獨立成功，無未解句型／意思障礙。改寫或延伸需實際回答引用，不用任意字數公式。情境按具體背景判斷，不要求不同大類標籤。

一次結算最多升一級，New 不在單回合跳級。未知證據本身不升降級。一次失敗只影響日程；連續兩個相關回合的首次無提示提取，都在句型／意思上確認失敗時，降一級，最低 Learning。小錯、未測及未知不算失敗，也不跳過未知紀錄湊成連續失敗。符合降級時本回合不再升級。

舊投影的累計數字保留為 baseline；新政策升級採可驗證、符合新條件的證據。投影數值本身不能補出缺失的首次提取、延遲、提示或具體情境。

## 6. 複習日程與弱點

複習日程依結算後狀態及該句型本回合證據計算：

| 狀態 | 指定提取整體獨立成功，且本回合無實質提示 | 指定提取失敗，或本回合需實質提示 |
|---|---:|---:|
| Learning | 3 天後 | 1 天後 |
| Usable | 7 天後 | 2 天後 |
| Automatic | 21 天後 | 2 天後 |

主句型指定提取是尾段；穿插句型是該題首次回答。實質提示採較短間隔優先。已有實際練習但未測或不足以判斷時，2 天後確認，不把未知記為失敗。以受支持的實際練習日為基準，不用較晚收尾／匯入日期延後。沒有實際練習的句型不改日程。日程到期與延遲成功是兩回事：隔天到期不一定已滿 24 小時。

弱點以具體「使用條件＋規則＋偏差」辨識，跨句型通用規則用 global，句型框架特有用 structure；不以相似句子或文法大類合併。

新弱點需在最近 10 個已結算真實回合中有至少兩個不同回合的合格 occurrence，含本次；每回合最多算一次。重試、模仿、立即自修、聽寫不確定不增加 recurrence。第一次保留觀察。建立後歷史 ledger 不因偵測窗口滑動而丟失。

最後一次犯錯之後，需兩個後續回合、兩個不同情境的首次適用機會均無該規則提示而正確使用，其中一次具 24 小時延遲，才解除。延遲基準包含該規則最近的機會、提示、修正及排練。沒有適用機會、逃避使用及未知不是成功。再次確認犯錯就 reopen 並重算解除窗口，保留舊證據；同回合犯錯優先於正向證據。正向使用不增加 occurrence／last_seen。

## 7. 保存、更正與恢復

只準備尚未作答，可結束並保留必要行政記錄，不產生學習成果或改變 mastered state。已保存未結算證據可恢復，但不計入已結算成功回合與反覆弱點窗口。

逐題保存失敗時停止追加題目，保留對話與已保存證據，回報失敗步驟及恢復動作。換聊天從最後保存的題目、回答或回饋階段接續；已回答題目不重算。若來源邊界真的無法判斷，只釐清必要缺口，不靠相同文字或日期猜去重。

收尾把結果、受支持的掌握／日程更新、弱點 ledger、回合 Applied 狀態及 identity registry 一起提交。相同操作重試回已完成，不增加計數；相同 identity 但不同內容回 conflict。結算失敗保留原回合及固定結果／計畫，恢復後才能開始新回合。只有讀回驗證成功才稱已保存。

收尾前聽寫更正以追加事件保留原文及原因，結算使用明確有效版本。收尾後只追加更正及影響分析，不覆寫已結算結果。若影響進度，先產生具體修復方案供使用者確認；獲確認後以獨立、可稽核的修復操作調整，避免把原回合再套用一次。

## 8. Plugin 與資料邊界

```text
sentence-structures-practice/
  plugins/sentence-structures/
    plugin.json
    skills/practice/SKILL.md
    scripts/                       # Python 3.9 相容的 repository、policy、CLI
  data/
    practice.sqlite3              # 教材、進度、回合、證據、弱點及索引
    config.json                   # root／timezone／schema 等配置，沒有另一套進度
    imports/<bundle>/             # 不可變原始回傳、正文、schema、規則及來源 manifest
    backups/<checkpoint>/         # 自足且可驗證的本地備份
    reports/                      # 可重建的核對與診斷報告
  tests/                          # 隔離 fixture 與測試 store
  docs/                           # 設計、使用與修復文件
  .agents/plugins/marketplace.json
  .codex/config.toml
```

主 skill 封裝教學及流程，supporting scripts 負責讀寫、確定性門檻、交易與恢復。質性判斷附原句及理由；程式不自行捏造語言觀察。日常不需額外載入 runtime/router/manager 指揮文件；本設計文件、glossary、ADR 與舊來源供維護和核對。

SQLite 是唯一可變學習資料權威；原始匯入快照是唯讀來源證據，報告是衍生資料。個人資料不進 plugin package 或安裝 cache。每次程式呼叫明確帶本專案 root，驗證實際路徑及資料標記，不從 cache 或任意聊天猜位置。

一次本地安裝／啟用後須驗證主 skill 可發現並能在本專案使用。來源更新走正式 reload／reinstall，不手改 cache。本版使用現有 Python／sqlite3 標準函式庫與主 skill，不需新增 MCP server。資料搬移時重新指定 root，避免寫回舊位置。

程式操作涵蓋讀取／選題、開始、保存原回答、保存評估／回饋、追加更正、暫停、結算／恢復、查看進度／診斷、dry-run 匯入／正式匯入、備份／匯出／還原及已確認修復。內部 IDs 由程式管理。

## 9. 資料一致性與備份

SQLite transaction 保證相關進度、弱點與 Session 一起生效；foreign keys、唯一鍵及版本檢查防止重複回合、兩個 active 回合、錯題寫入與 lost update。新結果、來源正文、更正事件與凍結計畫採不可變記錄；不原地重寫已結算證據。

提交前固定結果與計畫，記 absolute before／after 及證據引用；重試驗證原計畫，不從已更新計數再次加一。資料版本變動、損毀或身份衝突會具體回報並停止受影響操作。設定及原始檔使用同檔案系統的原子寫入與 hash 核對；檔案先完整保存驗證，才在資料庫中發布引用。

每次結算提交前建立完整本地 checkpoint，包含一致 SQLite 備份、所需原始來源、schema／policy／配置及校驗 manifest。備份 API 不以裸複製使用中的 DB 取代；正式啟用前測試備份可獨立讀取及還原。不自動刪除 checkpoint，提供手動完整匯出。

還原先驗證並備份現有資料，在獨立 staging root 重建。舊 checkpoint 不能直接抹掉較新的已結算 identity；須檢查後續已接受紀錄與固定計畫，能完整恢復才切換，無法證明時報 recovery watermark／缺口並停止受影響寫入。SQLite atomicity 與實際斷電 durability 分開報告，不把合成測試當作實機斷電驗證。

## 10. 舊資料遷移

以 [source-audit.md](source-audit.md) 的核對結果為基準，開工後重新全量唯讀匯出並比對來源變動。保留 100 個 canonical、投影、13 筆原回合、1 筆 Error、來源 metadata、三筆 ordered corrections 與兩份 plans，以及原規則快照。

目前來源無 Pending／Failed。保留 96 New、S001–S003 Learning、S005 Usable；不 replay Applied、不套新門檻回改歷史。S005 保留 9／3 並註記 secondary 落差；若未來判斷依賴有爭議證據，才釐清受影響部分。舊 resolved Error 保留原 key／Occurrences／blank body，不捏造 ledger。

Importer 同時保留 raw 與可驗證的 normalized read view，處理 v1、v2、列表格式及 legacy partial；不只讀第一段 result，完整保留 correction 順序與 plan。舊 metadata 缺 practiced 時從正文取得可確定的 secondary；未知 purpose／時間保持未知。來源 createdTime 與本地匯入時間分開。

先建立 dry-run parity report：筆數、ID、欄位、原文 hash、版本、更正鏈、計畫、參照及既有 warnings。通過後在新 staging learner store 一次發布 baseline；不覆蓋既有本地 learner store，同 bundle 重跑不重複匯入。來源若變成 Pending 或出現新矛盾，先依原政策核對，不能忽略或自動修正。

啟用後日常只讀寫本地資料。原 Notion 與原 ChatGPT Project 設定保留。未取得完整原 ChatGPT 對話；遷移交付說明會明列此限制，不宣稱保存完整逐字稿。

## 11. 實作與驗收

順序：固定本方案版本 → 建立 schema／repository／policy 與隔離測試 → 建主 skill／本地安裝 → 全量唯讀 export／dry-run → 核對並發布初始資料 → 真正測試練習入口及恢復。

驗收至少涵蓋：
